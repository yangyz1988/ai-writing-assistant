# 晋升型工作成果账本：产品设计

## 1. 产品定义

产品从“通用 AI 写作插件”重新定位为：

> 面向正在争取晋升的职场人，持续记录可量化成果，并生成让领导看见价值的周报、月报、述职和晋升材料。

用户购买的不是一次改写，而是一个长期维护的个人工作成果账本。产品负责减少遗漏、补齐证据、回顾承诺并把工作价值组织成适合汇报的表达；AI 写作只是最后的输出环节。

核心承诺：

> 重要成果不遗漏，工作价值说得清，每次汇报都有证据。

## 2. 目标用户与付费动机

### 2.1 首发用户

- 28–40 岁的项目经理、产品经理、运营负责人和新晋管理者。
- 每周需要向直属领导同步进度，每季度或半年需要述职。
- 同时负责多个项目，经常忘记早期成果、关键数据和跨部门贡献。
- 对晋升、绩效评价和职业形象有明确诉求，愿意为个人生产力工具付费。

### 2.2 不作为首发重点的用户

- 偶尔写一次文案的普通用户。
- 只需要语法润色或翻译的用户。
- 由公司统一采购工具、个人没有选择权的员工。
- 需要完整团队项目管理、审批或知识库的企业客户。

### 2.3 用户愿意付费的原因

1. 持续保存跨周、跨项目的工作上下文，通用对话式 AI 默认不具备这些上下文。
2. 自动发现“只有过程、没有结果”的记录，并追问数据、影响和证据。
3. 对照上周承诺检查完成、延期和遗漏，减少汇报失信。
4. 从同一份事实账本生成周报、月报、口头汇报和述职素材，避免重复整理。
5. 每项输出都能回溯原始记录，降低 AI 编造和事实错误。

## 3. 核心工作流

### 3.1 随手记录

用户在浏览网页、邮件、文档或聊天记录时选中文本，点击“记录为工作成果”。用户也可在扩展弹窗中手动输入。

每条记录包含：

- 原始内容；
- 日期；
- 所属项目；
- 类型：成果、数据、问题、协作、反馈或计划；
- 来源页面标题与地址，仅在用户主动记录时保存；
- 用户补充说明；
- 是否包含敏感信息的本地提示。

保存前展示内容和来源，用户确认后才进入账本。产品不自动扫描网页、邮件或聊天内容。

### 3.2 价值补全

系统根据记录判断是否缺少以下信息：

- 完成了什么；
- 相比原状态发生了什么变化；
- 有哪些数字或可验证证据；
- 影响了哪些用户、团队或业务指标；
- 用户本人承担了什么角色；
- 后续动作和截止时间是什么。

系统每次最多提出两个高价值问题，用户可以跳过。系统不得为缺失信息自行补造数字或事实；未补充内容保持为空或显示 `[待补充]`。

### 3.3 周度复盘

用户发起周报时，系统读取本周记录和上周计划，生成复盘草稿：

1. 本周最重要的三项成果；
2. 关键数据与业务影响；
3. 上周计划的完成、延期和取消状态；
4. 当前风险及需要领导支持的事项；
5. 下周计划及预期结果。

生成前先展示事实清单和缺失项。用户确认事实后才生成正式文本。

### 3.4 多格式输出

同一批已确认事实支持四种输出：

- 30 秒领导摘要：结论优先，不超过 200 字；
- 详细周报：成果、数据、问题、支持请求和下周计划；
- 口头汇报稿：适合 2–3 分钟表达；
- 述职素材：按项目持续积累，按季度或半年汇总。

输出必须区分事实、判断和计划。每个成果可展开查看其引用记录；复制输出时默认不附带来源链接。

## 4. 产品结构

首版扩展包含五个一级区域：

1. **今日记录**：快速新增并补全工作事项。
2. **成果账本**：按时间、项目和类型查看记录。
3. **本周复盘**：核对承诺、补齐事实并生成周报。
4. **汇报中心**：生成不同格式并保存版本。
5. **账户与额度**：管理 Pro 状态、用量和隐私设置。

现有“API 配置、写作模式、自定义模式、提示词模板”降级为高级设置，不继续作为产品主导航。通用划词改写保留为免费辅助能力，但不再承担核心定位。

## 5. 免费版与个人 Pro

### 5.1 免费版

- 使用用户自己的 API Key 进行基础划词改写；
- 最多保存 30 条成果记录；
- 仅生成基础周报；
- 保留最近 4 周记录；
- 支持本地数据导出和删除。

免费版必须能完整体验一次“记录—补全—周报”闭环，避免仅展示付费墙。

### 5.2 个人 Pro

- 不限成果记录，受合理使用限制；
- 自动对照上周计划；
- 项目维度的长期成果脉络；
- 领导摘要、详细周报、口头汇报和述职素材；
- 自定义领导偏好和表达风格；
- 搜索、筛选、导出与跨设备同步；
- 平台内置模型额度，无需配置 API Key。

建议验证价为 `¥29/月`、`¥199/年`。首轮访谈和付费测试只验证该价格，不同时测试多个复杂套餐。

### 5.3 付费触发点

- 用户保存第 25 条记录时提示容量；
- 用户首次生成领导摘要、口头汇报或述职素材时；
- 用户首次查看跨周项目成果脉络时；
- 用户完成第三次周报后展示年付选项。

不得在用户尚未完成一次有效周报前强制升级。

## 6. 核心数据模型

### AchievementRecord

- `id`：本地生成的唯一标识；
- `occurredAt`：事项发生时间；
- `capturedAt`：记录时间；
- `projectId`：可为空；
- `category`：achievement、metric、problem、collaboration、feedback、plan；
- `sourceText`：用户确认保存的原始内容；
- `summary`：用户确认后的简述；
- `impact`：结果或影响；
- `metrics`：结构化数据项；
- `role`：用户本人承担的角色；
- `nextAction` 与 `dueAt`：后续动作；
- `source`：可选的页面标题与地址；
- `sensitivity`：用户确认的敏感等级。

### WeeklyCommitment

- `weekId`；
- `description`；
- `expectedOutcome`；
- `status`：planned、completed、delayed、canceled；
- `evidenceRecordIds`；
- `explanation`。

### ReportDraft

- `periodStart` 与 `periodEnd`；
- `format`：executive_summary、weekly_report、spoken_update、review_material；
- `recordIds`；
- `confirmedFacts`；
- `content`；
- `createdAt` 与 `updatedAt`。

生成内容必须引用 `recordIds` 和 `confirmedFacts`，不得直接从未确认的页面内容生成。

## 7. 系统边界与数据流

### 扩展端

- 负责选中文本捕获、记录确认、账本界面、报告编辑和本地缓存。
- 免费 BYOK 请求继续从扩展直接调用用户配置的模型。
- 登录短期令牌只存 `chrome.storage.session`。
- 未经用户主动操作，不读取或上传页面内容。

### 服务端

- 负责账户、会员、额度、跨设备同步和平台模型网关。
- 每次平台模型调用都在服务端校验权益并幂等扣减额度。
- 默认不记录用户原文和生成正文；必要日志只包含账户、记录数量、字符长度、模型、耗时和结果状态。

### 生成流程

1. 扩展收集用户选定的记录 ID。
2. 用户确认待发送的事实摘要。
3. 服务端验证会员和额度。
4. AI 网关使用结构化事实生成指定格式。
5. 服务端返回正文和事实引用映射。
6. 扩展保存草稿并允许用户编辑、复制或删除。

## 8. 错误与安全处理

- 网络失败不丢失本地记录，报告生成可重试。
- 同一个生成请求使用幂等键，重试不得重复扣费。
- 令牌过期后清理会话并提示重新登录，不删除本地账本。
- 模型输出包含未知数字、姓名、日期或项目时标记为事实冲突，禁止直接复制前要求用户确认。
- 来源页面地址仅在用户主动勾选后同步；本地来源默认不参与分析日志。
- 提供一键导出、清空本地数据和申请删除云端数据的入口。

## 9. 首版范围

### 必须完成

- 手动新增成果记录；
- 从网页选中文本创建记录；
- 六类记录分类与项目归属；
- 至多两个价值补全问题；
- 上周计划与本周完成状态核对；
- 基础周报和 30 秒领导摘要；
- 事实确认与记录引用；
- 本地数据导出、删除；
- Free/Pro 功能守卫和用量展示。

### 暂不开发

- 自动读取邮箱或企业 IM；
- 团队协作、审批和管理员后台；
- 企业 SSO；
- 复杂项目管理和甘特图；
- 自动发送邮件或消息；
- 会议录音转写；
- 全量知识库或向量检索平台。

## 10. 成功指标与停止条件

首轮只招募符合目标画像的 20 名用户，连续使用四周。

### 激活

- 24 小时内保存至少 3 条记录；
- 7 天内完成第一份周报；
- 至少 60% 的入组用户完成激活。

### 留存

- 第 2 周仍保存记录的用户比例至少 40%；
- 四周内至少生成 3 份周报的用户比例至少 30%。

### 价值

- 用户自报每周整理汇报节省至少 20 分钟；
- 至少 50% 的有效用户认为产品帮助其发现过遗漏成果或缺失数据；
- 输出后平均人工修改时间不超过 5 分钟。

### 付费

- 在完成两份有效周报后展示 `¥29/月` 真实付费选项；
- 有效用户到付费的转化率目标不低于 8%；
- 20 名种子用户中至少 3 人完成真实付款。

如果四周后没有至少 3 人真实付款，不优先增加模板或降低价格。先访谈判断问题属于记录负担、生成质量、晋升诉求不强，还是持续上下文价值不足。若多数用户不愿持续记录，停止“成果账本”路线，改测浏览器行为内的一键捕获，而不是继续扩充报告类型。

## 11. 测试策略

- 单元测试：记录校验、周次计算、承诺状态、事实引用、Free/Pro 守卫和幂等请求。
- 组件测试：记录表单、补全问题、事实确认、空状态、过期会话和额度耗尽。
- 集成测试：从选中文本创建记录，再生成带引用的周报。
- 安全测试：未确认内容不得上传；过期令牌不可继续请求；Pro 权益不能由浏览器可写存储伪造。
- 用户测试：使用真实但脱敏的一周工作素材，观察从首次记录到复制周报的完整过程。
