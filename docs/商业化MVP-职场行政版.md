# 职场行政版商业化 MVP

## 1. 决策摘要

- 首发人群：20–500 人公司的行政、人事助理、运营助理与部门负责人。
- 核心承诺：在网页、邮件、IM 或文档中选中文本，30 秒生成可发送的正式表达。
- 收费方式：免费 BYOK + Pro 订阅。免费版降低安装门槛，Pro 出售免配置、专业模板和批量工作流。
- 首发价格：Pro `¥19/月` 或 `¥159/年`；连续使用 7 天后展示年付优惠。价格在 30 名付费用户前不频繁调整。
- 非目标：首期不做团队协作、品牌知识库、企业 SSO，也不承诺“无限高级模型”。

## 2. 产品分层与权益

| 能力 | 免费版（BYOK） | Pro |
| --- | --- | --- |
| 基础模式：正式化、润色、简化、翻译 | 可用，每日 10 次 | 不限基础调用，受公平使用限制 |
| 用户自己的 API Key | 支持 | 支持 |
| 平台内置额度 | 7 天/30 次试用 | 含每月 1,000 次标准改写额度 |
| 职场行政模板 | 6 个试用模板 | 全部 30 个 |
| 批量处理 | 每次最多 3 段 | 每次最多 30 段 |
| 自定义提示词与历史 | 最多 3 个模板、最近 30 条 | 不限模板、可搜索与导出 |
| 支持 | 社区/常见问题 | 邮件优先支持 |

说明：额度应按“标准改写次数”而非裸 Token 对用户展示。超长文本、高级模型或批处理会按实际成本消耗多个次数；明确显示预计消耗，避免争议。

## 3. 首发模板库（30 个）

每个模板使用同一输出原则：不编造事实、保留日期/金额/姓名等关键信息；信息不足时用 `[待补充]` 标记；仅输出成稿，不解释改写过程。

### 通知与公告

1. **正式通知**：将原文改写为可直接发送的内部通知；包含标题、事项、时间、对象、执行要求、联系人。
2. **会议通知**：生成会议主题、时间、地点/链接、参会人员、议程、会前准备和迟到说明。
3. **活动报名通知**：生成活动目的、参与对象、时间地点、报名方式、截止时间、注意事项。
4. **制度发布通知**：使用审慎正式语气，说明生效日期、适用范围、核心变化、查阅路径与咨询渠道。
5. **值班安排通知**：整理为日期、人员、职责、联系方式、交接要求和紧急升级方式。
6. **安全/紧急提醒**：用简洁明确的命令式表达，按“风险—立即行动—禁止事项—联系人”组织。

### 会议与汇报

7. **会议纪要**：整理为会议主题、结论、待办事项、负责人、截止时间、风险与下次会议。
8. **会议邀请邮件**：输出邮件主题和正文；明确会议目的、时间地点、参会要求、材料与 RSVP。
9. **周报整理**：将素材整理为本周完成、数据/成果、问题与风险、下周计划、需要支持。
10. **月度工作总结**：按目标达成、重点成果、问题复盘、资源需求、下月计划输出。
11. **向领导汇报**：先写一句结论摘要，再列进展、风险、需要决策的事项；语气客观克制。
12. **项目进度同步**：按当前状态、已完成、下一里程碑、阻塞项、责任人、时间点输出。

### 邮件与沟通

13. **正式邮件润色**：保留事实与诉求，补齐称呼、主题、正文、行动请求、落款占位。
14. **催办邮件**：礼貌但明确地说明待办、原约定时间、影响和新的反馈截止时间。
15. **跨部门协作请求**：说明背景、需配合事项、交付标准、负责人、截止时间与优先级。
16. **客户接待确认**：输出确认邮件，涵盖来访时间、地点、联系人、议程、交通/停车与变更联系方式。
17. **致歉与延期说明**：承认影响但不推诿；写明原因、补救措施、新交付时间和跟进人。
18. **IM 简洁沟通**：适合企业微信/钉钉，保留关键信息，分点表达，结尾明确希望对方的动作。

### 人事与行政

19. **入职通知**：生成入职时间、地点、联系人、需携带材料、报到流程和着装/交通提示。
20. **面试邀请**：输出职位、时间、形式、时长、参会者、准备材料和确认方式。
21. **面试反馈记录**：根据素材形成事实性评价，分能力匹配、亮点、风险、建议，不加入未提供信息。
22. **培训通知**：写清培训目标、对象、时间、地点、课程安排、签到要求与课前准备。
23. **请假/调休回复**：用规范且有人情味的语气说明审批结果、日期、交接要求和系统操作。
24. **办公物资申请**：整理为申请原因、物资明细、数量、预算/优先级、使用人、期望到位日期。

### 公文与规范表达

25. **请示稿**：按“请示事项—事实依据—方案/预算—请示意见”组织，并保留待审批项。
26. **工作函**：形成标题、主送单位、事项说明、需配合内容、时限、联系人和落款。
27. **通报**：客观说明事件、影响、处理决定、整改要求与时限，避免情绪化或定性过度。
28. **整改通知**：输出发现问题、整改标准、责任人、截止时间、复查方式和未完成后果。
29. **流程说明**：转为清晰 SOP：适用范围、前置条件、步骤、责任角色、时限、常见异常。
30. **合规正式化**：删除口语与模糊措辞，保留事实，标注任何需法务/主管确认的高风险表述。

## 5. 会员与后端开发任务

### P0：可以收费的闭环

1. 建立账号服务：邮箱验证码或手机号验证码登录；不要在扩展端保存长期访问令牌。
2. 建立权益服务：试用、订阅状态、周期、剩余额度、幂等的用量扣减。
3. 建立 AI 网关：扩展只把文本和模板 ID 发到后端；后端校验权益、限流、调用模型、记录用量后返回结果。
4. 建立支付订单：官网创建订单，支付回调由服务端验证签名；仅凭回调更新会员状态。
5. 扩展增加账户页：登录、当前计划、剩余额度、升级入口、管理订阅链接。
6. 增加功能守卫：前端仅用于体验提示，关键权益由后端每次请求校验。
7. 上线前准备：隐私政策、用户协议、退款规则、客服邮箱、数据删除请求入口。

### P1：提升转化与留存

1. 事件埋点：安装、完成配置、首次改写、模板点击、试用开始、支付页打开、支付成功、7 日留存。
2. 模板收藏与最近使用；不用记录用户完整敏感文本到分析系统。
3. 会员数据看板：活跃、试用转付费、续费、每个模板的使用/付费贡献。
4. 失败重试、模型降级与清晰错误提示；低成本模型作为默认。

### 安全边界

- 平台模型密钥只能存放在服务端密钥管理环境，绝不打进扩展包或返回浏览器。
- 文本默认只用于本次生成；日志仅记录必要的元数据（长度、模板 ID、耗时、结果状态），内容日志需用户明确同意。
- 支付回调、额度扣减、订阅状态转换必须是幂等操作。
- API 必须按账户、IP 和设备做速率限制；防止试用额度被批量滥用。

## 6. 验证节奏与停止条件

| 阶段 | 时间 | 目标 | 继续条件 |
| --- | --- | --- | --- |
| 种子测试 | 第 1–2 周 | 20 人完成 3 次真实任务 | 至少 10 人称愿意为“免配置+模板”付费 |
| 试用闭环 | 第 3–4 周 | 100 名激活用户 | 试用启动率 >= 15% |
| 收费验证 | 第 2 个月 | 10 名付费用户 | 试用到付费 >= 5% |
| 留存优化 | 第 3 个月 | 30 名付费用户 | 月续费意愿 >= 70% |

若“试用到付费”低于 3%，不要优先降价；先访谈未付费用户，判断问题是在结果质量、场景不刚需、额度不足，还是支付信任不足。
